# 漢方体質チェック 試験サイト（/kampo/）セットアップ・運用手順

ESSENCE薬局 武蔵小杉店の店頭 iPad で使う「体質チェック＋薬剤師のご提案支援」の試験版。
仕様の正本は `docs/kampo-spec.md`（実装指示書 v0.1）、仕様との差分は `docs/kampo-decisions.md`。

**既存の無料インフラ（Vercel + Upstash Redis）だけで動く。追加契約は不要。**
画面上では「診断」「処方」「治る」を使わず「体質チェック」「ご提案」と表記する。

## URL

| 用途 | URL | 誰が |
|---|---|---|
| ログイン（共通パスワード） | `/kampo/login/` | スタッフ |

| 改善アドバイス（養生）※PIN | `/kampo/check/<id>/advice/<type>/` | 薬剤師が開いて説明 |

**来店客の画面には体質の点数・漢方薬を出さない**（2026-10-25〜）。送信完了画面の下の「スタッフの方はこちら」→ PIN 入力 → その回の薬剤師の入力画面へ直行する（2026-10-29〜。長押しは廃止）。

## 初回セットアップ（Vercel の環境変数）

1. **KV**：`KV_REST_API_URL` / `KV_REST_API_TOKEN` は /yoyaku と共用。設定済みなら追加作業なし（データは `kampo:` プレフィックス）。
2. **KAMPO_PASSWORD**：店頭 iPad・PC のログイン用の共通パスワード。未設定なら `YOYAKU_ADMIN_KEY` が使われる。
3. **KAMPO_STAFF_PIN**：スタッフ画面の4桁PIN。未設定のうちは共通パスワードで代用され、画面に注意が出る。
4. **KAMPO_SESSION_SECRET**：Cookie の署名鍵（`openssl rand -hex 32`）。未設定でも動く（パスワードから派生）が、設定を推奨。
5. **KAMPO_SUPERVISOR_NAME**（例 `薬剤師 ○○ ○○`）、**KAMPO_SUPERVISOR_BIO**（任意の一文）：改善アドバイスの監修者表示。未設定なら監修欄は出さない（2026-10-28〜）。
6. **担当者の名簿**：スタッフ画面（`/kampo/staff/`）の「設定・データ」→「担当者の名簿」に1行1人で登録する（2026-10-29 第3弾〜。KV `kampo:staffnames`）。薬剤師の入力画面の上部で名簿から1回選ぶと、以降の記録に自動で入る。環境変数 `KAMPO_STAFF_NAMES`（カンマ区切り）を設定していれば、その名前も名簿に出る（任意）。
7. `KAMPO_RETENTION_YEARS`：保持年数（既定 3）。

環境変数は Preview 環境にも適用するよう設定する（試験中はプレビュー URL で使うため）。

## 試験サイトの公開方法（本公開はしない）

- 実装はブランチ `claude/jolly-mayer-khrsji` に push する。main には入れない。
- Vercel がブランチごとにプレビューデプロイ（`https://ex-labs-hp-git-<branch>-<team>.vercel.app` 形式）を作る。URL は GitHub の Deployments または Vercel ダッシュボードで確認する。
- プレビューにも共通パスワードが必要。Vercel 側の「Deployment Protection」が有効ならそのログインも挟まる（店頭 iPad で使うときは Vercel 側の保護を切るか、Bypass を設定する）。
- 本公開する場合は main にマージすれば `https://kabuexlabs.com/kampo/` で動く。

## 店頭での流れ

1. スタッフが iPad でログイン → `/kampo/check/new/` で識別（会員番号／電話／LINE表示名／識別なし）・入力者を選び、同意文を確認して START → 来店客に渡す（または聞き取り入力）。
2. 問診の順番（画面には STEP 1〜5 で表示）：基本情報（性別・年代・月経の状況・妊娠授乳＝任意）→ お悩み（大カテゴリー A〜H → 具体的な主訴 → 2つ以上なら「いちばん改善したいもの」→ その深掘り）→ 体質チェック（顔色はイラスト、睡眠は全員に8項目）→ 安全確認（薬の種類・漢方薬を飲んでいるか・お薬手帳・病気と手術歴・アレルギーと体調を崩した経験）→ 生活習慣（1問）→ 回答の確認 → 送信。主訴・深掘りで答えた症状は、あとの設問では聞かない（睡眠はチェック済みで表示）。回答は1問ごとに保存され、同じ URL で続きから答えられる。
3. 直ちに対応が必要な選択肢（急な神経症状・急な腫れと息苦しさ）を選ぶと、その場と送信完了画面に「すぐに近くのスタッフにお声がけください」が出て、スタッフ一覧の最上段に赤い印が付く。
4. 薬剤師の入力画面（担当者画面）の開き方：①送信完了画面の下の「スタッフの方はこちら」（スタッフが聞き取りで入力したときは「薬剤師の入力画面へ進む」）→ スタッフ PIN → いま回答した方の入力画面、または ②スタッフ画面（`/kampo/staff/`、PIN）の「本日のチェック」「直近のチェック（日付をまたいで20件）」「顧客検索 → 履歴」→「開く」（URL は `/kampo/staff/session/<チェックID>/`）。入力画面は、いちばん上の要約（担当者の選択・赤の受診のおすすめ・確認の進み具合）→ タブ「1. 確認する」（観察、お客様に聞いて確認するチェックリスト）→ タブ「2. 提案する」（AI の判定の棒グラフ・漢方薬の候補・養生・メモ・お客様用の結果・A4印刷・保存）の形（2026-10-31〜。④薬剤師の判定・③漢方薬の入力は廃止）。お客様に結果を見せるときは、薬剤師画面の「お客様用の結果を表示」（問診の直後にお客様が一人で見る形にはしない）。受診のおすすめは薬剤師画面（赤帯）だけに出し、薬剤師が口頭で伝えて「お客様に伝えた」を記録する。最初に画面上部の「担当者」を名簿から選ぶ（以降の記録に自動で入る）。妊娠中・授乳中の方には漢方候補を出さない（養生のご案内のみ）。舌はご本人が「薬剤師に見てもらう」を選んだときだけ①で入力する。担当者画面では、直ちに対応・未確認の帯、安全確認タグ（確認したら「確認した」を記録）、服用中の薬・持病・アレルギー（記入内容は口頭で確認）と食品と生薬の対応表、**薬剤師の観察（舌の色・形・苔・舌下静脈、顔色・爪、体格・声、妊娠授乳、服用中・体調を崩した漢方薬）を入力して保存**（再計算）→ **薬剤師の判定を記録**（記録するまで AI の判定と漢方薬の候補は出ない）→ AI の判定（6タイプ＋寒熱の暫定スコアと判定との比較）、所見と回答の一覧、候補表と推薦理由、選定とメモを保存 → 一覧で「提案済み」。
5. 来店客への説明（結果シート）：判定の記録後に担当者画面の「体質の説明画面」を開き、iPad の画面で見せながら説明する（主となる体質・併存する傾向・寒熱の傾向・説明・改善アドバイス。点数と漢方薬は出さない）。持ち帰り用は「印刷する」で A4 縦（2ページ目に主となる体質の改善アドバイス）。提案保存時に「画面で説明／A4印刷して渡す」を記録する。
6. **お客様に iPad を渡す前に「来店客モードへ戻る」を押す**（スタッフ Cookie が消える。放置しても12時間で失効）。
7. 違和感のあった設問・文面・候補は `docs/kampo-feedback.md` に書きため、JSON を直して再デプロイ。

## スコアリングと漢方薬の選定（詳細は docs/kampo-decisions.md の 2026-10-24）

- 体質（**暫定**。フェーズ3で証の判定条件に置き換える）：所見の草案の重みで、同じ所見は1回、同じ group は同じタイプへ1回分（group 内の最大）だけ数える。回答済み（あり・なし）の所見だけ理論最大点に入れる。点数 = raw/max（0〜100）。区切り（20／40／60、主となる体質＝最高、併存＝最高の70%以上または60以上かつ20以上）は 2026-10-24 版のまま。来店客には点数を出さない。
- 五臓：所見の organs で同じ方法で集計（スタッフ画面と選定に使う）。熱寄りのときは陰虚が陽盛より強ければ「虚熱」、そうでなければ「実熱」。
- 生活習慣は判定に使わず、養生の一言（types.json の tips）にだけ使う。
- 安全確認タグはスコアと別。タグが付いた回答があると候補はすべて「要確認」（薬剤師の確認が済むまで提案を確定しない）。
- **漢方薬の選定は二段階**：STEP 1 いちばん改善したい主訴と詳細問診で特定した症状 → 承認効能に持つ漢方薬だけを候補群に（ほかの主訴と詳細問診の随伴症状は候補に加えない）／STEP 2 候補群の中で気血水・寒熱・虚実・五臓・主訴の詳細・随伴症状を照合（適合度）／STEP 3 最も適合するものを1件推薦（合うものがなければ推薦しない）／STEP 4 安全性で除外・要確認／STEP 5 理由①〜④。
- 重み・しきい値は src/lib/kampo/recommend.ts の SELECTION（初期値）。気血水 0.45、五臓 0.15、寒熱 0.1、熱の種類 0.05、体力の範囲 0.1、使用目標に当たる回答（体質チェックなど）0.1×件数（上限0.3）、使用目標に当たる主訴・詳細問診の回答 0.1×件数（上限0.2）、随伴症状も効能に含む 0.05×件数（上限0.1）。適合 0.45 以上かつ（気血水 20以上 か 使用目標に当たる回答あり）。
- 安全性の規則は src/lib/kampo/safety.ts（HERB_CHECKS・HERB_NOTES・safetyContext）。

## 処方マスタ（src/data/kampo/formulas.json）の項目

| 項目 | 意味 | 使う段階 |
|---|---|---|
| efficacy | 承認された効能・効果の全文 | 表示 |
| indications | 効能・効果の諸症を症状コードに対応づけたもの（記載順）。requires は条件つきの効能 | STEP 1 |
| useTarget / strength | 使用目標（しばり）と体力の範囲 def/mid/exc | STEP 2 |
| types / thermal / heat / organs | 気血水の対象、寒熱（温める／中間／冷ます）、冷ます対象の熱（実熱／虚熱）、五臓 | STEP 2 |
| signs | 使用目標・随伴症状・症状の性質に当たる所見ID（findings.json） | STEP 2 |
| action | 漢方医学的な作用の説明（効能・効果とは別） | 理由② |
| targetLabel | 他の候補と比べたときの特徴（短い語） | 理由③ |
| cautionHerbs / contraindications | 注意生薬（注意事項・要確認）／当たれば除外する安全フラグ | STEP 4 |
| verified | 製品の添付文書で効能を確認済みか（初期値は全件 false） | スタッフ画面に「未確認」 |

症状コードの一覧は同じファイルの symptoms。主訴（complaints.json）と深掘りの選択肢の symptoms／also と対応する。formulas.json は scratchpad の生成スクリプトで作った初期値なので、以後はこの JSON を直接編集してよい。

## データ

- Upstash Redis：`kampo:s:<id>`（セッション。TTL 3年）、`kampo:sessions`（索引）、`kampo:c:<id>`（顧客）、`kampo:idx:member:*` / `kampo:idx:phone:*`、`kampo:customers`、`kampo:audit`（閲覧・保存の記録、最大5000件）。
- 保持期限切れの掃除は `/kampo/staff/` を開いたときに自動で走る。手動なら `curl -H "Authorization: Bearer $CRON_SECRET" https://<host>/api/kampo/purge`。
- バックアップ：スタッフ画面の「CSV書き出し」（全セッション・回答・提案）を週次で保存する。Upstash 側の自動バックアップにも依存。
- 削除依頼：現状は Upstash コンソールで `kampo:s:<id>` と索引を手で消す（管理画面からの削除は次版）。
