# 漢方体質診断 試験サイト（/kampo/）セットアップ・運用手順

ESSENCE薬局 武蔵小杉店の店頭 iPad で使う「体質の整理＋薬剤師の候補検討支援」の**開発・試作版**。
仕様の正本は `docs/kampo-spec-v2.md`（2026-10-25 受領の最終実装用マスタープロンプト）、設計は `docs/kampo-v2-design.md`、仕様との差分・判断は `docs/kampo-decisions.md`。
旧仕様（v0.1）は `docs/kampo-spec.md`。

**判定の重み・カットオフ・主訴と処方の対応・構成生薬・安全規則はすべて草案（未検証）。実患者向けには使わない。**
AI による確定診断・自動処方・服薬の自動推奨はしない。患者向けの画面に漢方薬は出さない（仕様書 §25⑪）。
画面上では「診断」「処方」「治る」を使わず「体質チェック」「ご説明」「漢方薬」と表記する。

**既存の無料インフラ（Vercel + Upstash Redis）だけで動く。追加契約は不要。**

## URL

| 用途 | URL | 誰が |
|---|---|---|
| ログイン（共通パスワード） | `/kampo/login/` | スタッフ |
| 受付（識別・舌モード・同意） | `/kampo/check/new/` | スタッフ → iPad を渡す |
| 設問（1画面1問・すべて選択式） | `/kampo/check/<id>/q/<n>/` | 来店客（または聞き取り） |
| 回答確認（修正・送信） | `/kampo/check/<id>/confirm/` | 来店客 |
| 送信完了（スタッフにお声がけ） | `/kampo/check/<id>/done/` | 来店客 |
| 途中再開 | `/kampo/check/<id>/` | 最初の未回答へ飛ぶ |
| スタッフPIN | `/kampo/staff/pin/` | スタッフ |
| 本日の一覧・顧客検索・CSV | `/kampo/staff/` | スタッフ |
| 担当者画面（安全性・主訴・体質・追加質問・候補・除外・提案） | `/kampo/staff/session/<id>/` | 薬剤師 |
| 体質の説明（レーダー・体質の特徴。漢方薬なし）※PIN | `/kampo/check/<id>/result/` | 薬剤師が来店客に説明 |
| 養生アドバイス ※PIN | `/kampo/check/<id>/advice/<qi_def〜yin_def・cold・heat>/` | 薬剤師が来店客に説明 |
| 顧客履歴 | `/kampo/staff/customer/<id>/` | 薬剤師 |

すべて noindex・no-store。未ログインでどの URL を開いても `/kampo/login/` に戻る。体質の説明・養生アドバイスは PIN も必要（患者の回答導線は送信完了で終わる）。
送信完了画面の**右下を1.2秒長押し**すると PIN 入力 → その回の担当者画面へ直行する。

## 初回セットアップ（Vercel の環境変数）

1. **KV**：`KV_REST_API_URL` / `KV_REST_API_TOKEN` は /yoyaku と共用（データは `kampo:` プレフィックス）。
2. **KAMPO_PASSWORD**：店頭 iPad・PC のログイン用の共通パスワード。未設定なら `YOYAKU_ADMIN_KEY`。
3. **KAMPO_STAFF_PIN**：スタッフ画面の4桁PIN。未設定のうちは共通パスワードで代用（画面に注意）。
4. **KAMPO_SESSION_SECRET**：Cookie の署名鍵（`openssl rand -hex 32`）。設定を推奨。
5. **KAMPO_SUPERVISOR_NAME**・**KAMPO_SUPERVISOR_BIO**：養生アドバイスの監修者表示。
6. **KAMPO_STAFF_NAMES**：担当薬剤師の氏名（カンマ区切り）。提案・除外理由の確認・原因生薬の記録で選択式になる。
7. `KAMPO_RETENTION_YEARS`：保持年数（既定 3）。

## 店頭での流れ（v2）

1. スタッフが iPad でログイン → `/kampo/check/new/` で識別・舌チェックのモード（ご自分で／スタッフが確認）・入力者を選び、同意文を確認して START → 来店客に渡す。
2. 来店客の回答（すべて選択式・自由記述なし。「特にない」「わからない」はほかと同時に選べない）：
   1. 基本情報：性別 → 年代 →（男性以外）月経の状況 → 妊娠・授乳
   2. 安全性確認：いまの緊急症状 → 治療中の病気 → 飲んでいる薬の種類（文字で絞り込み）→（漢方薬を選んだら）漢方薬の名前（ひらがな・漢字で検索）→ アレルギー → 漢方薬で体調を崩したこと →（ありなら）その漢方薬と症状
   3. お悩み：カテゴリー（A〜H・複数）→ 具体的な症状（73項目・複数）→（2つ以上なら）いちばん改善したい症状を1つ
   4. いちばん改善したい症状の詳細（1問・複数選択）＋ 選んだ症状に応じた安全上の確認
   5. いつから・生活への影響 → 共通体質（B1〜B13。回答済みの事項は出さない。B7 むくみ・B11 月経・B13 舌は条件つき）→ 生活習慣
   6. 回答確認（修正は各設問へ）→ 送信 → 送信完了（「スタッフにお声がけください」）
   緊急症状を選ぶとその場で強い注意を出し、送信完了画面にも「すぐにスタッフにお知らせください」を出す。
3. 右下を長押し → PIN → 担当者画面（上から）：
   - **安全性**（状態5種：緊急対応優先／除外／安全性確認待ち／薬剤師確認必要／必要な確認完了）、副作用歴（漢方・反応・原因生薬・除外対象の生薬。未特定は「暫定」）、服用中の漢方薬と構成生薬
   - **① 主訴**：優先主訴・その他の主訴・詳細・修飾情報（対象症状つき）・経過・安全上の確認
   - **② 体質**：主証（保留なら理由）・併存証・主訴関連の証・寒熱・虚実・五臓・整合性、判定の根拠（加点した所見）、低スコアの証（折りたたみ）、未確認事項
   - **追加質問**（選択式。優先順：安全性 → 処方候補の鑑別 → 証の鑑別 → 五臓）。回答すると所見に統合して再計算。**舌の観察（薬剤師）**は患者のイラスト選択とは別の情報源として保存し、判定では薬剤師を優先
   - **③ 候補**：優先検討候補／検討候補／安全性・情報確認待ち（主訴対応・製品情報が未確認のあいだは全件ここ）。処方・製品・主訴関連（効能の語）・一致／不一致所見・体質適合・追加確認・禁忌と注意・情報源
   - **④ 除外・対象外**：理由・副作用歴・共通生薬・状態・確認者・日時。「除外理由を確認済みにする」で確認者を記録
   - **副作用歴の原因生薬の記録**（確認資料・判断理由つき。記録しても除外は自動解除しない）
   - 回答一覧・所見一覧（回答状態と情報源）・提案の保存
4. 必要なら「体質の説明（来店客向け）」を開いて一緒に見る（漢方薬は出ない。印刷可）。
5. **お客様に iPad を渡す前に「来店客モードへ戻る」を押す**（スタッフ Cookie が消える）。

- 各ファイルの `review.status` が確認状態：draft（草案）／source_checked（資料確認済み）／expert_checked（専門家確認済み）／validated（検証済み）／needs_update（更新確認待ち）。**草案以外にするときは source・reviewer・reviewedAt が必須**（検証でエラー）。項目ごとに `review` を書けばファイルの既定を上書きできる。
- 主訴対応・製品情報が「専門家確認済み」以上になるまで、候補は「優先検討候補」「検討候補」に入らない。
- 編集後は `npm run test:kampo`（`npm run check` に含む）でマスタ検証と §23 のテストが走る。未定義の所見・主訴・生薬の参照、重みが 1/2/3 以外、「特にない」「わからない」の欠落、修飾情報の対象なし、などはエラー。
- 設問を変えたら `questions.json` の `version` を更新する（v2 は `v2-` で始める。セッションに記録され、v1 と区別する）。

## 判定と候補選定の要点（詳細は docs/kampo-v2-design.md の ⑥〜⑧）

- 所見の回答状態は present／absent／unknown／not_asked／declined。未質問を「なし」にしない。表示した選択肢だけを absent にする。主訴の一覧で選ばなかった主訴は absent にしない。
- 気血水6証：present の所見を 3/2/1 点で加点。同一所見は1回、相関グループ内は最大点のみ。暫定カットオフ（候補／強く示唆）気虚5/8・血虚5/7・気滞5/8・瘀血5/7・水滞5/8・陰虚5/8。
- 主証：候補以上の証のうち、独立グループ2以上・3点の所見あり・2位と2点以上の差、を満たさなければ保留。併存証は §8 の5条件（主証と共通の所見・グループを除いても候補点以上 など）。
- 寒・熱：別々に加点し、各5点以上かつ独立グループ2以上で傾向。両方なら混在の可能性。冷えとほてりの併存だけで上熱下寒とは判定しない。虚・実：数値カットオフ未確定のため独立グループ2以上で傾向（点数は補助）。五臓：主証・併存証を支持する所見のうち、その臓の所見が独立2グループ以上で「関連の可能性」。
- 候補：優先主訴の⑤主訴対応だけから抽出（体質だけで処方を足さない。根拠がない主訴は候補なし）→ 安全性 → 重要鑑別所見 → 体質の適合（補助）→ 追加質問 → 4分類。参考点は草案。
- 副作用歴：漢方薬の構成生薬と1種でも共通する候補は除外（原因生薬が未特定なら暫定除外）。構成生薬が草案のままで共通生薬がない場合は「確認待ち」。

## データ

- Upstash Redis：`kampo:s:<id>`（セッション。TTL 3年。回答・薬剤師の追加質問・原因生薬の記録・除外理由の確認・判定の要約（snapshot）・提案）、`kampo:sessions`、`kampo:c:<id>`、`kampo:idx:*`、`kampo:customers`、`kampo:audit`（閲覧・送信・追加質問・記録・提案・CSV、最大5000件）。
- v1（2026-10-24 版まで）のセッションは担当者画面で回答の文言と当時の結果だけを表示する（v2 の判定は再計算しない）。
- 保持期限切れの掃除は `/kampo/staff/` を開いたときに自動で走る（Vercel Cron は追加していない）。
- バックアップ：スタッフ画面の「CSV書き出し」（判定の要約・候補の分類・回答・追加質問・記録）。

## 開発・テスト

- ロジックのテスト：`npm run test:kampo`（マスタ検証＋仕様書 §23 の全項目）
- ローカル動作確認：`.env` に KV と KAMPO_* を入れて `npx astro dev --port 4322 --host 127.0.0.1`。KV が無い環境では Upstash 互換のモックで代用した。
- 主な実装：`src/lib/kampo/`（masters／findings／flow／assess／safety／recommend／staffq／compute／store／auth／icons）、`src/pages/kampo/`、`src/components/kampo/`（RadarChart・AdviceBlock・ResultTabs・StaffQuestion・StaffName・QMark）、`src/layouts/KampoLayout.astro`。ルート保護は `src/middleware.ts` → `kampoGuard`。
